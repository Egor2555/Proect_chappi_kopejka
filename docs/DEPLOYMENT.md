# Развёртывание Chappi Edition

Приложение рассчитано на сервер с Node.js 20+ и PostgreSQL. Планшет открывает веб-адрес сервера в обычном браузере; Node.js и база на планшете не нужны при облачном размещении.

## Что подготовлено в репозитории

- `Dockerfile` — сборка серверного контейнера.
- `railway.toml` — конфигурация health-check и запуска для Railway.
- `.env.example` — список необходимых переменных.
- `/api/health` — проверка сервера и подключения к PostgreSQL.

## Переменные окружения

Обязательные:
- `DATABASE_URL` — строка подключения к PostgreSQL.
- `JWT_SECRET` — длинный случайный секрет для подписи токенов.
- `INITIAL_ADMIN_USERNAME` — имя первой учётной записи администратора.
- `INITIAL_ADMIN_PASSWORD` — первоначальный пароль администратора (не менее 10 символов).

Необязательная:
- `PGSSL=true` — включить TLS для PostgreSQL, если этого требует провайдер.

Не добавляйте реальные значения в GitHub. Их нужно вносить только в секретные переменные окружения хостинга.

## Общий порядок запуска

1. Создать постоянную PostgreSQL-базу у выбранного хостинг-провайдера.
2. Создать web service из репозитория `Egor2555/Proect_chappi_kopejka`, ветка `main`, используя Dockerfile.
3. Перед первым запуском задать перечисленные переменные окружения.
4. Указать health-check path `/api/health`.
5. Запустить сервис и проверить, что health-check возвращает `ok: true`.
6. Войти первоначальным администратором и сразу сменить пароль в разделе «Профиль».
7. Создать работников, назначить их в бригады и создать учётные записи только тем, кому нужен вход.
8. Ввести расценки на нужный месяц и проверить тестовый сценарий до внесения реального производства.

## Перед реальной эксплуатацией

- Включить регулярные резервные копии PostgreSQL у провайдера и проверить восстановление.
- Проверить стоимость и постоянство выбранного тарифа; не использовать временную базу, которая автоматически удаляется.
- Ограничить доступ к административной учётной записи.
- Не импортировать старые `data.json` без отдельной процедуры миграции.
- Не включать персональные начисления и автоматическое распределение «Счастливой копейки», пока не утверждены отсутствующие формулы.

**Важно:** конфигурация и инструкции подготовлены, но облачный сервис не создан и не опубликован. Создание платных ресурсов требует отдельного действия владельца аккаунта у выбранного провайдера.
