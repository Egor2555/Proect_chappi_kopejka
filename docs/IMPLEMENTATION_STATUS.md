# Chappi Edition — статус реализации

Последнее обновление: 2026-10-04  
Ветка: main

## Реализовано в текущем каркасе

- Node.js/Express сервер и PostgreSQL схема.
- Планшетный веб-интерфейс с крупными элементами управления.
- Вход по логину/паролю, хеширование паролей, ограничение частоты входа.
- Роли Работник / Бригадир / Администратор с серверной проверкой доступа.
- Ограничение бригадира собственной бригадой.
- Создание работников и пользователей администратором, назначение в бригаду, отметка только работавших сотрудников.
- Справочник стартовых шести длин 60×40, добавление новых типоразмеров и архивирование без изменения старой истории.
- Расценки доступны для просмотра всем; ввод цены выполняется при закрытии месяца после показа фактически произведённых объёмов.
- Ежедневный ввод выпуска бригады сразу по всем активным длинам.
- Заказы с несколькими типоразмерами, приоритетом, частичным выполнением и автоматическим завершением.
- Распределение излишка в следующие подходящие заказы по приоритету и дате создания; нераспределённый остаток учитывается на складе.
- Складской журнал, отгрузки, проверка достаточности остатка и отдельный зачёт оплаты по отгрузке.
- Месячный отчёт показывает количество по типоразмерам и введённые цены; закрытие рассчитывает стоимость каждого дня и персональные начисления по фактическому составу работников.
- Общий фонд как отдельный журнал поступлений/расходов.
- Архив закрытых месяцев за последние шесть месяцев; архив работников, изделий и завершённых заказов.
- Журнал изменений, журнал входов, запись входа в административный режим.
- Экспорт резервной копии JSON без хешей паролей.
- Безопасный dry-run восстановления: проверка формата, внешних связей, дубликатов и состава данных без изменения БД.
- Исправление производства через сторно с причиной, обратными складскими движениями и аудитом.
- Модуль выбора победителя «Счастливой копейки» с криптографической случайностью и модульными тестами.

## Проверка

GitHub Actions выполняет:
- синтаксическую проверку серверной и клиентской частей;
- модульные тесты денежных вычислений, распределения излишков и «Счастливой копейки»;
- тест PostgreSQL-схемы и начальных типоразмеров;
- HTTP smoke test на временной PostgreSQL: вход, роли, работники, присутствие, расценки, заказы, излишки, склад, отгрузка, оплата, отчёт, фонд, закрытие месяца, архив и резервный экспорт.

Последний полный smoke test на временной PostgreSQL прошёл успешно.

## Что намеренно не выдумано и пока не включено

1. **Счастливая копейка.** Подтверждены случайный выбор одного работника из получателей выплаты, значок 🏆, однократный выбор в конце месяца, сохранение победителя и отсутствие победителя при нулевом остатке. Функция случайного выбора написана и протестирована. Но точная формула суммы остатка и полный критерий списка получателей не восстановлены, поэтому автоматическое включение в закрытие месяца пока заблокировано.
3. **Восстановление резервной копии.** Экспорт JSON реализован; автоматический импорт/восстановление в новую базу ещё требует отдельного безопасного сценария и теста.
4. **Развёртывание.** Dockerfile и конфигурация Railway подготовлены, но реальный облачный сервис и постоянная база данных не создавались. Нужны выбранный хостинг, подключённая PostgreSQL и безопасные секреты. Нельзя считать приложение уже опубликованным.
5. **Перенос старых данных.** Старые V5.031/V5.034 остаются историческими версиями. Импорт их `data.json` не выполнялся; перед переносом нужна отдельная проверенная миграция.

## Статус

**MVP обновлён под подтверждённую реальную схему расценок и персонального расчёта. Следующие этапы: «Счастливая копейка», безопасное восстановление резервной копии, реальное облачное развёртывание, перенос старых данных и финальная проверка на рабочем сценарии.**
