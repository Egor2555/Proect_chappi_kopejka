# Chappi Edition — Учёт столбов

Новая версия системы учёта производства столбов 60×40. Проект начинается с чистого репозитория, но опирается на накопленные требования и уроки предыдущих версий.

## Цели

- Ежедневный учёт фактического производства по длинам.
- Учёт бригад, работников и рабочего времени.
- Исторические расценки и проверяемый расчёт заработка.
- Заказы, очередь, выполнение частями и автоматическое завершение.
- Складской учёт через движения продукции.
- Отгрузки, отчёты, архив и журнал изменений.
- Резервное копирование и восстановление.

## Принципы

1. Данные не должны теряться при изменении функций.
2. Исторические операции сохраняют исходные характеристики и применённые расценки.
3. Склад рассчитывается из зарегистрированных движений, а не из произвольного ручного остатка.
4. Важные изменения журналируются.
5. Финансовые расчёты должны быть воспроизводимыми и проверяемыми.
6. Неясные правила производства и оплаты фиксируются как вопросы, а не угадываются.

## Статус

**Этап:** рабочий MVP-каркас, проверяемый CI.  
**Текущее состояние:** производство, заказы, склад, отгрузки, расчёт закрытия месяца, аудит и резервный экспорт реализованы; backup проходит проверку целостности и dry-run восстановления.  
**Текущее состояние:** «Счастливая копейка» автоматически и случайно выбирает одного из допущенных работников при закрытии месяца; резервное восстановление реализовано в безопасном режиме с сохранением существующих учётных записей и паролей. Оставшиеся критические этапы — облачное развёртывание и перенос старых данных.  
**Важно:** старые V5.031/V5.034 — исторические контрольные точки, а не исходный код новой системы.

## Локальный запуск

Требуется Node.js 20+ и PostgreSQL.

1. Создайте базу PostgreSQL.
2. Скопируйте `.env.example` в `.env` и заполните `DATABASE_URL`, длинный случайный `JWT_SECRET` и первоначальный пароль администратора.
3. Установите зависимости: `npm install`.
4. Запустите: `npm start`.
5. Откройте адрес сервера на порту `8080` (или значение `PORT`).

При первом запуске схема создаётся автоматически, добавляются шесть базовых длин и первая бригада. Первоначальный администратор создаётся только если заданы `INITIAL_ADMIN_USERNAME` и `INITIAL_ADMIN_PASSWORD`.

Никогда не добавляйте `.env`, реальные пароли, токены или дампы базы в Git.

## Проверки

- `npm run check` — синтаксис серверной и клиентской частей плюс модульные тесты.
- `npm test` — тесты доменных расчётов.
- `/api/health` — проверка доступности приложения и соединения с PostgreSQL.

## Состояние разработки

Основной MVP-контур собран и защищён автоматическими проверками. Резервный экспорт валидируется, включая внешние связи и дубликаты, а dry-run восстановления не изменяет базу. Реальное восстановление реализовано без переноса хешей паролей: существующие учётные записи сохраняются, а бизнес-данные backup восстанавливаются с переназначением пользовательских ссылок по имени пользователя. «Счастливая копейка» при закрытии месяца случайно выбирается среди работников, фактически работавших в расчётные дни; результат сохраняется и не меняется при повторном просмотре.
